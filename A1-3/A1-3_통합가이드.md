## 🔍 1. 서비스 기획 및 프로젝트 기본 구조 파트

### <a id="sec-1"></a>📌 [1] AI 웹 서비스 기획 및 3개 이상 페이지/섹션 UI 네비게이션 설계
* **관련 명세**: `최소 3개 이상의 페이지 또는 섹션(메뉴 이동 가능)이 있다. / 서비스 기획서 제출`

#### 👩‍🏫 이해도 체크 (Checklist)
* **확인 질문**: "만들고자 하는 AI 웹 서비스의 타겟 사용자, 핵심 목적 및 3개 이상의 페이지/섹션 네비게이션을 어떻게 설계해야 할까요?"
* **자가진단 난관 지표**: 아이디어 없이 단일 텍스트 상자 하나만 덩그러니 두고 페이지 이동 기능이 없어 단순 API 테스트용 화면에 그침.
* **통과 기준 (이해 완료 판정)**:
  - 서비스 대상(타겟)과 해결하고자 하는 문제 및 AI 기능이 제공하는 유저 가치(Value)를 정의할 수 있다.
  - 메인(Hero) 섹션, 서비스 소개 섹션, AI 기능 상호작용 섹션 등 최소 3개 이상의 메뉴(네비게이션) 구조를 설계하고 스크롤/페이지 이동을 구현한다.
* **퍼실리테이터 개입 가이드**: "교육생에게 '단순한 파이썬 스크립트 실행이 아니라, 실제 사용자가 방문하여 편리하게 이용하는 하나의 완결된 웹 서비스 제품(Product)'이라는 사용자 경험 시각을 제시한다."
* **참고 레퍼런스**: [MDN Web Docs - 웹 사이트 기획과 구조 설계](https://developer.mozilla.org/ko/docs/Learn/Getting_started_with_the_web) (사전지식: 기획서 작성 및 웹 서비스 이해)

#### 🙋‍♂️ 교육생 예상 질문 & 답변 (Q&A)
* **예상 질문**: "네비게이션 메뉴 버튼을 눌렀는데 화면이 이동하지 않거나 404 Not Found 에러가 납니다."
* **학습자 난관**: 싱글 페이지(SPA) 스타일의 앵커 탭 이동(`href="#section-ai"`)과 여러 HTML 파일(`about.html`) 간 링크 이동 방식의 차이를 혼동함.
* **기본 개념**: 
  - 단일 HTML 파일 내에서 섹션을 이동할 때는 `<a href="#ai-section">` 과 각 섹션의 `<section id="ai-section">` ID를 연결함.
  - 여러 파일로 나눌 때는 `index.html`, `about.html`, `service.html` 간의 상대 경로(`href="about.html"`)가 올바른지 확인해야 함.
* **퍼실리테이팅 가이드**:
  - 네비게이션 버튼의 `href` 속성 값과 실제 렌더링되는 HTML 섹션 태그의 `id` 문자열이 철자까지 일치하는지 점검해 준다.

### <a id="sec-2"></a>📌 [2] 프론트엔드와 백엔드(api/) 관심사 분리 아키텍처
* **관련 명세**: `프론트(HTML/CSS/JS)와 백엔드(api/) 구조가 구분되어 있다.`

#### 👩‍🏫 이해도 체크 (Checklist)
* **확인 질문**: "프론트엔드(HTML/CSS/JS)와 백엔드(`api/` 서버리스 함수)의 역할을 독립적으로 분리하여 구성해야 하는 이유는 무엇일까요?"
* **자가진단 난관 지표**: 브라우저 프론트엔드 JavaScript 코드 상에서 OpenAI API를 직접 호출하려다가 API 키 유출 위험과 CORS 차단 문제에 직면함.
* **통과 기준 (이해 완료 판정)**:

  - 백엔드(`api/` 파이썬 코드)는 보안이 요구되는 API 키 보관, 외부 AI API 통신, 데이터 가공 및 응답 반환을 담당함을 설명할 수 있다.

* **예상 질문**: "`document.querySelector`로 버튼을 잡아서 이벤트를 붙였는데 `TypeError: Cannot read properties of null` 에러가 뜹니다."

  - `const response = await fetch('/api/recommend', { method: 'POST', body: ... })` 비동기 통신으로 JSON 응답을 성공적으로 수신할 수 있다.
* **퍼실리테이터 개입 가이드**: "교육생에게 '카카오톡 메시지를 주고받을 때 화면 전체가 깜빡이지 않는 것처럼, 사용자 경험을 매끄럽게 유지하는 싱글 페이지 아작스(AJAX) 통신의 이점'을 알려준다."
* **참고 레퍼런스**: [MDN Web Docs - Fetch API 사용하기](https://developer.mozilla.org/ko/docs/Web/API/Fetch_API/Using_Fetch) (사전지식: JavaScript Promise 및 async/await)

#### 🙋‍♂️ 교육생 예상 질문 & 답변 (Q&A)
* **예상 질문**: "`fetch('/api/recommend')` 호출 시 브라우저 콘솔창에 `CORS header 'Access-Control-Allow-Origin' missing` 에러가 발생합니다."
* **학습자 난관**: 로컬 `file://` 경로에서 직접 HTML을 열었거나 도메인이 다른 백엔드 호출 시 브라우저 보안 교차 출처 차단이 일어남.
* **기본 개념**: 
  - 브라우저는 보안상 서로 다른 도메인/포트 간의 통신 시 서버의 CORS 허용 헤더(`Access-Control-Allow-Origin: *`)를 검증함.
  - 배포 환경이나 `vercel dev` 모드에서는 동일 Origin(`/api/...`)으로 요청되므로 문제가 해결됨.
* **퍼실리테이팅 가이드**:
  - 백엔드 파이썬 응답 헤더에 CORS 허용 헤더를 추가하거나 `vercel dev` 명령어로 개발 환경을 구동하게 안심시킨다.

### <a id="sec-11"></a>📌 [11] HTTP POST 요청 바디 파싱 및 JSON 응답 반환
* **관련 명세**: `프론트엔드 요청 파싱 / 필요한 패키지 반환 / 응답 포맷 정의`

* **참고 레퍼런스**: [Python http.server 공식 문서](https://docs.python.org/ko/3/library/http.server.html) (사전지식: 파이썬 I/O 스트림 및 JSON)

* **예상 질문**: "Python 서버리스 함수에서 `json.loads(self.rfile.read(...))`를 실행할 때 `json.decoder.JSONDecodeError`가 발생합니다."
* **학습자 난관**: 프론트엔드 `fetch()`에서 `headers: {'Content-Type': 'application/json'}` 및 `body: JSON.stringify(data)` 처리를 누락함.

### <a id="sec-13"></a>📌 [13] CORS 헤더 설정 및 응답 프로토콜 명세
* **관련 명세**: `프론트엔드와 백엔드 간 응답 처리 / HTTP Header 설정`

#### 👩‍🏫 이해도 체크 (Checklist)

* **자가진단 난관 지표**: 파이썬 응답 헤더에 `Content-Type: application/json`을 넣지 않아 브라우저가 응답 데이터를 일반 텍스트로 인식함.
* **통과 기준 (이해 완료 판정)**:
  - `self.send_header('Content-Type', 'application/json; charset=utf-8')` 헤더를 설정할 수 있다.
  - `self.send_header('Access-Control-Allow-Origin', '*')` 및 `Access-Control-Allow-Headers`를 추가하여 CORS 차단을 방지할 수 있다.
* **퍼실리테이터 개입 가이드**: "교육생에게 '응답 헤더는 포장지 겉면에 데이터 내용물이 JSON임을 알려주는 라벨 규격'임을 숙지시킨다."
* **참고 레퍼런스**: [MDN Web Docs - CORS 개념 및 해결책](https://developer.mozilla.org/ko/docs/Web/HTTP/CORS) (사전지식: HTTP Response Header)

#### 🙋‍♂️ 교육생 예상 질문 & 답변 (Q&A)
* **예상 질문**: "서버리스 함수가 응답을 반환했는데 프론트엔드 `response.json()`에서 파싱 에러가 납니다."
* **학습자 난관**: 백엔드가 JSON이 아닌 찌꺼기 문자열이나 500 HTML 에러 페이지를 응답으로 반환함.
* **기본 개념**: 
  - `response.json()`을 부르기 전에 `if (!response.ok)` 로 HTTP 상태 코드가 200 범위인지 먼저 확인해야 파싱 크래시를 막음.
* **퍼실리테이팅 가이드**:
  - `response.ok` 체크 로직을 프론트엔드 `fetch()` 다음에 보강하도록 가이드한다.

### <a id="sec-15"></a>📌 [15] GitHub & Vercel 연동 자동 CI/CD 배포 파이프라인
* **관련 명세**: `GitHub와 Vercel을 연동해 배포한다. / 배포 URL에서 전체 기능 동작`

#### 👩‍🏫 이해도 체크 (Checklist)
* **확인 질문**: "GitHub 저장소에 코드를 `git push`하면 Vercel이 이를 감지하여 자동으로 빌드 및 재배포(CI/CD)를 수행하는 워크플로우는 어떻게 작동할까요?"
* **자가진단 난관 지표**: 수동 파일 업로드 방식을 사용하다가 코드 수정 시마다 배포 과정이 꼬이거나 버전 관리가 안 됨.
* **통과 기준 (이해 완료 판정)**:
  - GitHub 계정과 Vercel 계정을 연결하고 프로젝트 저장소를 Import 하여 배포할 수 있다.
  - `git push origin main` 실행 시 Vercel 빌드 로그가 감지되고 배포 URL이 갱신됨을 확인한다.
* **퍼실리테이터 개입 가이드**: "교육생에게 '개발자가 코드를 저장소에 올리기만 하면 컨베이어 벨트가 작동하여 전 세계에 자동 출하(배포)되는 현대적 CI/CD 파이프라인'의 편리함을 경험하게 한다."
* **참고 레퍼런스**: [Vercel Git Integration 공식 가이드](https://vercel.com/docs/deployments/git) (사전지식: Git 커밋 및 Push)

#### 🙋‍♂️ 교육생 예상 질문 & 답변 (Q&A)
* **예상 질문**: "GitHub에 코드를 `git push` 했는데 Vercel 사이트에 변경된 최신 디자인이 반영되지 않습니다."
* **학습자 난관**: Vercel 빌드 오답(Build Error) 발생 또는 브라우저 캐시(Cache)로 인한 구버전 표시.

  - 빌드가 성공했다면 브라우저 강제 새로고침(`Ctrl + F5` 또는 `Cmd + Shift + R`)으로 캐시를 비워야 함.
* **퍼실리테이팅 가이드**:

### <a id="sec-16"></a>📌 [16] API 키 유출 시 긴급 보안 대응 및 커밋 이력 정돈 (BFG)

#### 👩‍🏫 이해도 체크 (Checklist)

* **자가진단 난관 지표**: 키가 유출되었음에도 코드를 수정하여 위에 덮어씌워 커밋(Git History에 키가 영구 남음)하고 안심함.

  - 2단계: Git 이력에서 BFG Repo-Cleaner 등을 이용해 영구 삭제하거나 새 저장소로 이관한다.
* **퍼실리테이터 개입 가이드**: "교육생에게 '지갑을 분실했을 때 카드사에 전화를 걸어 카드를 정지시키는 것이 최우선이듯, 유출된 키의 무효화 조치가 최우선 과제임'을 강조한다."
* **참고 레퍼런스**: [GitHub 문서 - 리포지토리에서 중요한 데이터 제거](https://docs.github.com/ko/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository) (사전지식: Git 히스토리 및 보안)

#### 🙋‍♂️ 교육생 예상 질문 & 답변 (Q&A)
* **예상 질문**: "GitHub에 커밋을 푸시하자마자 GitHub Secret Scanning으로부터 API 키가 유출되었다는 경고 메일이 왔습니다."
* **학습자 난관**: GitHub의 자동 봇 탐지로 키 유출을 통보받음.
* **기본 개념**: 
  - GitHub은 퍼블릭 저장소에 API 키 패턴이 감지되면 자동으로 봇이 해당 키를 포착하여 알림을 보냄.
  - 이미 유출된 키는 더 이상 안전하지 않으므로 즉시 폐기하고 신규 키를 발급받아 Vercel 대시보드에만 넣어야 함.
* **퍼실리테이팅 가이드**:
  - 즉시 API 키를 폐기하도록 가이드하고 `.env` 파일이 `.gitignore`에 등록되었는지 재확인시킨다.

### <a id="sec-17"></a>📌 [17] 로컬 개발 환경과 Vercel 배포 환경의 차이점 및 vercel dev
* **관련 명세**: `로컬 환경과 배포 환경의 차이를 이해하고, 배포 후 문제를 수정·재배포`

* **통과 기준 (이해 완료 판정)**:

  - 상대 경로(`/api/...`) 호출이 로컬과 배포 서버 양쪽에서 동일하게 작동함을 이해한다.
* **퍼실리테이터 개입 가이드**: "교육생에게 '시뮬레이터(vercel dev)를 통해 배포 전 로컬에서 클라우드 환경을 사전에 시험 조종해 보는 훈련'을 안내한다."
* **참고 레퍼런스**: [Vercel CLI vercel dev 가이드](https://vercel.com/docs/cli/dev) (사전지식: CLI 환경 및 로컬 서버)

* **학습자 난관**: `api/generate.py` 파일의 파이썬 핸들러 이름이나 폴더 경로 구조 미준수.

* **퍼실리테이팅 가이드**:

### <a id="sec-18"></a>📌 [18] 배포 문제 진단 및 브라우저/Vercel 로그 디버깅
* **관련 명세**: `배포 후 발생한 문제를 어떤 순서로 진단하고 수정했는지 설명`

#### 👩‍🏫 이해도 체크 (Checklist)
* **확인 질문**: "Vercel 배포 후 AI 기능이 동작하지 않거나 HTTP 500 에러가 발생할 때 Vercel Deployment Logs와 브라우저 개발자 도구로 진단하는 순서는 무엇일까요?"
* **자가진단 난관 지표**: 화면에 에러가 나면 원인을 추적하지 않고 막막해하며 코드를 무작정 지우고 다시 씀.
* **통과 기준 (이해 완료 판정)**:
  - 1단계: 브라우저 개발자 도구(F12) Network 탭에서 HTTP 응답 상태 코드(4xx/5xx)와 Response 메시지를 확인한다.
  - 2단계: Vercel 대시보드의 Deployment Logs 탭에서 파이썬 백엔드 스택 트레이스(Traceback)를 조회하여 수정할 수 있다.
* **퍼실리테이터 개입 가이드**: "교육생에게 '전반적인 시스템 트러블슈팅의 표준 2단계 진단법(클라이언트 네트워크 탭 1차 검사 -> 서버 런타임 로그 2차 검사)'을 습관화시킨다."
* **참고 레퍼런스**: [Vercel 프로젝트 로그 확인 가이드](https://vercel.com/docs/observability/runtime-logs) (사전지식: 웹 디버깅 및 Log 추적)

#### 🙋‍♂️ 교육생 예상 질문 & 답변 (Q&A)
* **예상 질문**: "배포 사이트에서 AI 기능을 실행하면 'Server Error (500)'만 뜨고 구체적인 에러 원인을 알 수 없습니다."
* **학습자 난관**: 프론트엔드 화면 콘솔만 확인하고 서버리스 백엔드의 파이썬 트레이스백 로그를 확인하지 않음.
* **기본 개념**: 
  - HTTP 500 에러는 백엔드 파이썬 코드 실행 중 예외(Exception)가 터졌음을 의미함.
  - Vercel 대시보드의 'Logs' 탭에 들어가면 파이썬의 몇 번째 줄에서 무슨 에러가 났는지 정확한 로그를 확인할 수 있음.
* **퍼실리테이팅 가이드**:
  - Vercel Logs 화면을 함께 보며 에러 발생 행(Line)과 에러 메시지를 해석하는 법을 지도한다.

## 🐍 8. 사용된 기술 스택 & 핵심 파이썬/JS 개념 가이드

이 영역은 `A1-3 AI 웹 서비스 빌딩` 미션에 사용된 핵심적인 파이썬 백엔드(Vercel Serverless Functions) 및 바닐라 웹 프론트엔드 개념과 함수들을 정리한 가이드입니다.

### 1. 핵심 파이썬 및 웹 프론트엔드 개념 (Core Concepts)

#### ① HTML5 시맨틱 구조화와 DOM Tree (`document.querySelector`, `addEventListener`)
* **개념:** HTML5 문서의 구조적 의미를 전달하는 시맨틱 태그로 작성된 문서를 브라우저가 해석하여 생성한 객체 트리가 DOM(Document Object Model)입니다.
* **이유:** JavaScript가 브라우저 내의 HTML 요소(버튼, 입력창, 결과 영역)를 탐색하고 클릭/입력 이벤트를 감지하여 화면을 동적으로 변경하는 바탕이 됩니다.
* **코드 예시:**
  ```javascript
  // DOM 요소 탐색
  const submitBtn = document.querySelector('#submit-btn');
  const resultDiv = document.querySelector('#result-area');

  // 이벤트 리스너 등록
  submitBtn.addEventListener('click', async (event) => {
      event.preventDefault();
      resultDiv.textContent = 'AI 결과를 생성 중입니다...';
  });
  ```

#### ② CSS3 미디어 쿼리 기반 반응형 레이아웃 (`@media`, `Flexbox/Grid`)
* **개념:** 디바이스의 화면 너비(Width)를 감지하여 데스크톱, 태블릿, 모바일 화면 환경에 맞게 레이아웃 배치를 유연하게 재조정하는 CSS3 디자인 기술입니다.
* **코드 예시:**
  ```css
  /* 기본 데스크톱 레이아웃 */
  .container {
      display: flex;
      flex-direction: row;
      max-width: 1200px;
  }

  /* 768px 이하 모바일 화면 처리 */
  @media (max-width: 768px) {
      .container {
          flex-direction: column;
          padding: 10px;
      }
  }
  ```

#### ③ 비동기 HTTP 통신과 프로미스 처리 (`fetch()`, `async/await`)
* **개념:** 브라우저 화면의 전체 새로고침 없이 백엔드 서버리스 함수(`/api/...`)로 데이터를 송수신하는 JavaScript의 표준 비동기 데이터 통신 기술입니다.
* **코드 예시:**
  ```javascript
  async function generateAIResponse(promptText) {
      const response = await fetch('/api/recommend', {
          method: 'POST',
          headers: { 'Content-Type': 'application/json' },
          body: JSON.stringify({ prompt: promptText })
      });
      
      if (!response.ok) {
          throw new Error('서버 응답 오류가 발생했습니다.');
      }
      
      const data = await response.json();
      return data.result;
  }
  ```

#### ④ Vercel Serverless Functions 파이썬 런타임 구조 (`BaseHTTPRequestHandler`)
* **개념:** Vercel 클라우드가 파이썬 함수를 서버리스 엔드포인트로 실행할 때 요구하는 표준 저수준 HTTP 요청 처리 클래스 구조입니다.
* **코드 예시:**
  ```python
  from http.server import BaseHTTPRequestHandler
  import json
  import os

  class handler(BaseHTTPRequestHandler):
      def do_POST(self):
          # 1. 요청 바디 읽기
          content_length = int(self.headers.get('Content-Length', 0))
          body_bytes = self.rfile.read(content_length)
          data = json.loads(body_bytes.decode('utf-8'))
          
          # 2. 비즈니스 로직 및 응답 생성
          result_data = {"status": "success", "result": "AI 추천 결과..."}
          
          # 3. HTTP 응답 송신
          self.send_response(200)
          self.send_header('Content-Type', 'application/json; charset=utf-8')
          self.send_header('Access-Control-Allow-Origin', '*')
          self.end_headers()
          self.wfile.write(json.dumps(result_data).encode('utf-8'))
  ```

#### ⑤ 클라우드 환경변수 보안 관리 (`os.environ.get()`, Vercel Secrets)
* **개념:** API 키를 소스코드에 포함시키지 않고, Vercel 대시보드의 Environment Variables 세팅에 등록하여 실행 런타임 시에만 `os.environ` 메모리로 읽어 들이는 보안 표준입니다.
* **코드 예시:**
  ```python
  import os

  api_key = os.environ.get("OPENAI_API_KEY")
  if not api_key:
      # API 키 미설정 시 안전한 500 에러 응답
      self.send_response(500)
      self.end_headers()
      self.wfile.write(b'{"error": "API Key is missing"}')
  ```

#### ⑥ 클라이언트 UX 상태 관리 (Loading, Success, Error State)
* **개념:** AI API 호출의 시작부터 종료까지 1) 로딩 스피너 표시, 2) 성공 시 화면 결과 렌더링, 3) 실패 시 에러 경고 메시지 렌더링을 제어하는 프론트엔드 상태 처리 패턴입니다.

### 2. 자주 사용되는 내장 함수 & Web API 메서드 (Built-in Functions & Web APIs)

#### ① `fetch(url, options)`
* **설명:** 브라우저 환경에서 서버로 비동기 HTTP 요청을 보내고 Promise 객체를 반환합니다.

#### ② `JSON.stringify()` & `JSON.parse()` (JS)
* **설명:** JavaScript 객체를 네트워크 전송용 JSON 문자열로 직렬화하거나, 반대로 수신된 JSON 문자열을 JS 객체로 파싱합니다.

#### ③ `element.textContent` vs `element.innerHTML`
* **설명:** DOM 요소에 텍스트를 삽입할 때 `textContent`를 사용하여 XSS(크로스 사이트 스크립팅) 공격을 예방하고 안전하게 문자를 출력합니다.

#### ④ `self.rfile.read(content_length)` (Python BaseHTTPRequestHandler)
* **설명:** 파이썬 HTTP 서버리스 핸들러에서 수신된 클라이언트의 요청 바이트 스트림(Body)을 `Content-Length` 크기만큼 읽어옵니다.

#### ⑤ `os.getenv(key, default)` (Python)
* **설명:** 시스템 환경변수 값을 안전하게 읽어오며, 값이 없을 경우 지정한 디폴트 값을 반환합니다.
