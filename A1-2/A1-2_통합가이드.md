## 🔍 1. CLI 및 입력 처리 파트

### <a id="sec-1"></a>📌 [1] argparse를 활용한 CLI 인자(-date) 정의 및 처리
* **관련 명세**: `argparse를 활용하여 CLI로 실행 가능해야 한다. 필수 옵션: -date "YYYY-MM-DD"`

#### 👩‍🏫 이해도 체크 (Checklist)
* **확인 질문**: "CLI 환경에서 사용자 입력을 받기 위해 sys.argv 대신 argparse 라이브러리를 사용할 때 얻을 수 있는 구조적 장점은 무엇일까요?"
* **자가진단 난관 지표**: `sys.argv`를 사용하여 인자 순서에 의존하는 하드코딩 방식을 사용하다가 인자가 하나라도 누락되면 `IndexError`를 일으키거나 도움말 문구를 출력하지 못함.
* **통과 기준 (이해 완료 판정)**:
  - `argparse.ArgumentParser` 객체를 생성하고 `--date` (또는 `-date`) 필수 옵션을 `required=True`로 지정할 수 있다.
  - 인자 입력이 누락되었을 때 자동으로 사용법(usage) 안내 메시지를 터미널에 출력하고 종료됨을 확인한다.
* **퍼실리테이터 개입 가이드**: "교육생에게 '사용자가 프로그램을 어떻게 써야 할지 모를 때 --help 만으로 도움말이 나오도록 만드는 표준 CLI 인터페이스 개발의 중요성'을 인지하도록 가이드한다."
* **참고 레퍼런스**: [Python argparse 공식 문서](https://docs.python.org/ko/3/library/argparse.html) (사전지식: 파이썬 모듈 import 및 파이썬 기본 데이터 타입)

#### 🙋‍♂️ 교육생 예상 질문 & 답변 (Q&A)
* **예상 질문**: "터미널에 `python travel_planner.py --date "2026-03-15"`를 입력했는데 `unrecognized arguments` 에러가 납니다."
* **학습자 난관**: argparse 설정 시 `-date`와 `--date` 옵션 선언의 차이점이나 인자 이름을 오타로 작성하여 인식을 못 함.
* **기본 개념**: 
  - GNU/POSIX CLI 표준에 따라 단기 옵션은 대시 1개(`-d`), 장기 옵션은 대시 2개(`--date`)를 사용하는 것이 표준적 관례임.
  - 명세에서 `-date` 또는 `--date`로 요구하므로, `parser.add_argument('-date', '--date', required=True, help="여행 날짜 (YYYY-MM-DD)")` 처럼 둘 다 지원하도록 등록하는 것이 가장 안전함.
* **퍼실리테이팅 가이드**:
  - `add_argument()` 함수에 등록된 인자 명칭과 실제 터미널에서 입력한 플래그 명칭이 대소문자 및 대시 개수까지 일치하는지 확인하도록 유도한다.

## 🔍 3. REST API & HTTP 통신 프로토콜 파트

### <a id="sec-7"></a>📌 [7] HTTP 요청 메서드(GET vs POST)의 차이점 및 사용 기준
* **관련 명세**: `REST API의 요청/응답 구조와 HTTP 메서드(GET/POST)의 차이를 말로 설명`

#### 👩‍🏫 이해도 체크 (Checklist)
* **확인 질문**: "카카오/네이버 지도 검색 API 호출 시 GET 방식을 사용하고, OpenAI/Gemini API 호출 시 POST 방식을 사용하는 기본적인 기준과 차이점은 무엇일까요?"
* **자가진단 난관 지표**: GET과 POST의 차이를 모르고 모든 API 호출 시 파라미터를 URL에 얹거나 바디(Body)에 얹어 405 Method Not Allowed 등의 오류를 마주함.
* **통과 기준 (이해 완료 판정)**:
  - GET은 서버의 자원을 조회/검색할 때 사용하며, 인자를 URL 쿼리 스트링(`?query=...`)으로 전달함을 설명할 수 있다.
  - POST는 서버에 데이터를 제출/생성 요청할 때 사용하며, 큼직한 프롬프트나 설정값을 요청 본문(JSON Body)에 담아 전달함을 설명할 수 있다.
* **퍼실리테이터 개입 가이드**: "교육생에게 '엽서를 보낼 때 겉면에 주소를 적는 것(GET URL 파라미터)과 편지 봉투 안에 내용을 넣어 보낼 때(POST Body)의 보안성 및 데이터 용량 차이' 비유로 지도한다."
* **참고 레퍼런스**: [MDN Web Docs - HTTP 요청 메서드](https://developer.mozilla.org/ko/docs/Web/HTTP/Methods) (사전지식: 웹 HTTP 통신 기본)

#### 🙋‍♂️ 교육생 예상 질문 & 답변 (Q&A)
* **예상 질문**: "GET 요청을 보낼 때 쿼리 스트링에 한글 검색어를 넣었더니 400 Bad Request 또는 깨짐 현상이 발생합니다."
* **학습자 난관**: URL 경로상에 포함될 수 없는 한글/특수문자의 퍼센트 인코딩(Percent Encoding) 처리 필요성을 간과함.
* **기본 개념**: 
  - URL 규격상 ASCII 범위를 벗어나는 한글 문자(예: "제주 맛집")는 `urllib.parse.quote()` 또는 `requests` 라이브러리의 `params` 딕셔너리 매핑을 통해 `%EC%A0%9C%EC%A3%BD...` 형태로 인코딩되어 전송되어야 함.
* **퍼실리테이팅 가이드**:
  - `requests.get(url, params={'query': '제주 맛집'})` 처럼 `requests`의 `params` 파라미터를 사용하면 라이브러리가 자동 URL 인코딩을 처리해 준다는 팁을 제공한다.

### <a id="sec-8"></a>📌 [8] HTTP 상태 코드 분석 및 상태별 대응 가이드
* **관련 명세**: `외부 API 호출에서 발생하는 대표 오류(인증/쿼터/네트워크/파싱) 대응`

#### 👩‍🏫 이해도 체크 (Checklist)
* **확인 질문**: "API 호출 결과 HTTP 응답 상태 코드가 401, 403, 429, 500으로 각각 반환되었을 때, 이를 구별하여 처리해야 하는 원인은 무엇일까요?"
* **자가진단 난관 지표**: API 호출 실패 시 모든 에러를 단순 "API 에러"로 뭉뚱그려 처리하여 문제 원인을 파악하지 못함.
* **통과 기준 (이해 완료 판정)**:
  - 401 (Unauthorized): API 키 유효하지 않음 또는 헤더 양식 오타.
  - 403 (Forbidden): 권한 부족, 도메인/IP 미등록, 계정 차단.
  - 429 (Too Many Requests): 사용 량(Quota) 초과 또는 단위 시간당 요청 수 제한 초과.
  - 500/503 (Server Error): 제공자 서버 장애.
* **퍼실리테이터 개입 가이드**: "교육생에게 '응답 상태 코드를 확인하는 것은 의사의 진찰 체온/혈압을 확인하는 첫 걸음'임을 파악하게 한다."
* **참고 레퍼런스**: [MDN Web Docs - HTTP 상태 코드](https://developer.mozilla.org/ko/docs/Web/HTTP/Status) (사전지식: HTTP 통신 기본)

#### 🙋‍♂️ 교육생 예상 질문 & 답변 (Q&A)
* **예상 질문**: "API를 몇 번 테스트했더니 갑자기 HTTP 429 에러가 발생하면서 호출이 거부됩니다."
* **학습자 난관**: 무료 계정의 Rate Limit(분당 요청 횟수 제한) 또는 잔액(Credit) 부족 현상을 인지하지 못함.
* **기본 개념**: 
  - HTTP 429는 짧은 시간 안에 너무 많은 요청을 보냈거나(RPM 초과), API 서비스의 이용 한도/무료 크레딧이 다 닳았을 때 발생함.
  - 프로그램에서 일정 시간 기다렸다가 재시도하거나(Exponential Backoff), 사용자에게 쿼터 초과 메시지를 안내해야 함.
* **퍼실리테이팅 가이드**:
  - 사용 중인 API 개발자 콘솔 사이트(OpenAI Platform / Kakao Developers)에 접속하여 본인 계정의 잔액 및 일일 사용량을 점검하도록 가이드한다.

### <a id="sec-9"></a>📌 [9] API 인증 헤더(Authorization Header) 구조 이해
* **관련 명세**: `Kakao Local(키 헤더) / Naver Local Search(Client ID/Secret 헤더)`

#### 👩‍🏫 이해도 체크 (Checklist)
* **확인 질문**: "API 인증 정보를 URL 파라미터가 아닌 HTTP Request Header에 담아 송신하는 이유는 무엇일까요?"
* **자가진단 난관 지표**: 헤더 키 이름이나 접두사(Prefix, 예: `KakaoAK `, `Bearer `)를 빠뜨려서 계속해서 인증 거부 401 상태를 받음.
* **통과 기준 (이해 완료 판정)**:
  - Kakao: `headers={'Authorization': f'KakaoAK {REST_API_KEY}'}`
  - Naver: `headers={'X-Naver-Client-Id': client_id, 'X-Naver-Client-Secret': client_secret}`
  - API 문서에 규정된 정확한 헤더 키명과 포맷 형태를 준수하여 구현할 수 있다.
* **퍼실리테이터 개입 가이드**: "교육생에게 'URL은 웹 서버 로그 등에 노출되기 쉬우나 헤더 영역은 더 안전하게 신원증명(ID/PW, Token)을 전달하는 통로'임을 설명한다."
* **참고 레퍼런스**: [Kakao Local API 개발 가이드](https://developers.kakao.com/docs/latest/ko/local/dev-guide) (사전지식: HTTP Header 개념)

#### 🙋‍♂️ 교육생 예상 질문 & 답변 (Q&A)
* **예상 질문**: "카카오 API 호출 시 `Authorization: KakaoAK {REST_API_KEY}` 헤더를 넣었는데도 계속 401 Unauthorized 에러가 납니다."
* **학습자 난관**: `KakaoAK` 뒤의 띄어쓰기(공백 1칸) 누락 또는 JavaScript 키 등 잘못된 종류의 키를 가져와 넣음.
* **기본 개념**: 
  - 카카오 REST API 인증 시에는 반드시 `KakaoAK` 접두사와 한 칸의 공백을 두고 REST API 키를 이어 붙여야 함 (`KakaoAK 1234567...`).
  - 카카오 내 애플리케이션 설정에서 Native App 키나 Admin 키가 아닌 **REST API 키**를 사용했는지 재확인이 필요함.
* **퍼실리테이팅 가이드**:
  - 헤더 문자열 f-string 작성부에 공백이 빠져 붙어있지 않은지 코드의 세밀한 오타를 짚어준다.

### <a id="sec-10"></a>📌 [10] LLM API 프롬프트 설계를 통한 JSON 형식 강제
* **관련 명세**: `반드시 JSON으로 파싱 가능한 텍스트를 생성하도록 프롬프트를 설계`

#### 👩‍🏫 이해도 체크 (Checklist)
* **확인 질문**: "LLM이 불필요한 인사말이나 마크다운 마크업(```json ...) 없이 오직 순수한 JSON 데이터만 출력하도록 강제하는 프롬프트 엔지니어링 기법은 무엇일까요?"
* **자가진단 난관 지표**: LLM에 날짜만 주고 "여행지 추천해줘"라고 요청하여 자연어 서술형 문장이 나와 다음 단계 프로그램 파싱이 불가능해짐.
* **통과 기준 (이해 완료 판정)**:
  - System Prompt 및 User Prompt 상에 출력 형식을 JSON 스키마 명세로 명확히 주입할 수 있다.
  - OpenAI의 `response_format={"type": "json_object"}` 또는 Gemini의 `response_mime_type="application/json"` 설정을 활용할 수 있다.
* **퍼실리테이터 개입 가이드**: "교육생에게 'LLM을 인간 답변자가 아닌, 프로그램 파이프라인의 데이터를 생성해 내는 API 모듈로 다루는 기법'을 경험하게 유도한다."
* **참고 레퍼런스**: [OpenAI Structured Outputs 가이드](https://platform.openai.com/docs/guides/structured-outputs) (사전지식: 프롬프트 엔지니어링 기초)

#### 🙋‍♂️ 교육생 예상 질문 & 답변 (Q&A)
* **예상 질문**: "LLM이 JSON 응답 앞뒤로 '네, 추천 정보입니다:' 같은 설명 문장을 붙여서 반환하여 파싱이 깨집니다."
* **학습자 난관**: 프롬프트의 JSON 출력 강제 지시가 약하거나 API의 JSON 모드 매개변수를 활성화하지 않음.
* **기본 개념**: 
  - 프롬프트 맨 첫 줄과 끝 줄에 `Return ONLY a valid JSON object. Do not include any explanations, markdown code blocks, or intro text.` 지시어를 명시함.
  - 최신 LLM API 제공자의 JSON 모드 기능을 코드 파라미터 수준에서 설정하면 100% 순수 JSON만 반환받을 수 있음.
* **퍼실리테이팅 가이드**:
  - API 매개변수 설정법과 정규식/문자열 슬라이싱으로 ```json 과 ``` 표식을 걷어내는 방어적 파싱 보조 함수 작성을 안내한다.

### <a id="sec-11"></a>📌 [11] 1차 추천 결과 JSON 스키마 검증 및 파싱
* **관련 명세**: `1차 JSON 최소 스키마: recommended_city, weather, events, reason`

#### 👩‍🏫 이해도 체크 (Checklist)
* **확인 질문**: "LLM이 생성한 JSON 텍스트를 `json.loads()`로 파싱한 후, 필수 키(Key) 4개 존재 여부와 데이터 타입을 코드 레벨에서 사전 검증(Validate)하는 것이 왜 필수적일까요?"
* **자가진단 난관 지표**: `json.loads()`가 성공했더라도 LLM이 `recommended_city` 대신 `city`라는 엉뚱한 키 이름을 반환하여 이후 로직에서 `KeyError`가 뿜어냄.
* **통과 기준 (이해 완료 판정)**:
  - `data = json.loads(response_text)` 후 필수 키 `["recommended_city", "weather", "events", "reason"]`가 모두 존재하는지 반복문이나 pydantic/jsonschema 로 검증한다.
  - `events` 키의 값이 문자열 리스트(`list`) 형적인지 검증할 수 있다.
* **퍼실리테이터 개입 가이드**: "교육생에게 'LLM의 출력은 유연하지만 언제든 환각이나 키 명칭 변형이 일어날 수 있으므로 코드 레벨에서의 스키마 검문소 작성이 필수적임'을 각인시킨다."
* **참고 레퍼런스**: [Python json 내장 모듈 공식 문서](https://docs.python.org/ko/3/library/json.html) (사전지식: 파이썬 딕셔너리 구조)

#### 🙋‍♂️ 교육생 예상 질문 & 답변 (Q&A)
* **예상 질문**: "LLM 응답을 파싱했는데 `KeyError: 'recommended_city'` 에러가 납니다."
* **학습자 난관**: LLM이 키 이름을 `recommended_location`이나 `target_city` 등으로 다르게 생성함.
* **기본 개념**: 
  - LLM은 프롬프트 요구사항을 가끔 미세하게 이탈하여 키 이름을 유사어로 대체할 수 있음.
  - 코드에서 `data.get('recommended_city')` 처럼 안전한 조회 방식을 쓰고, 필수 키가 누락되었을 경우 스키마 오류 예외를 다루어 재시도로 넘겨야 함.
* **퍼실리테이팅 가이드**:
  - `KeyError` 방지를 위한 `.get()` 활용법과 스키마 검증 전용 함수(`validate_schema(data)`) 작성을 조언한다.

### <a id="sec-12"></a>📌 [12] LLM JSON 파싱 실패 시 재시도(Retry) 메커니즘
* **관련 명세**: `LLM JSON 파싱 실패: 재요청 1회 또는 필수 키만 다시 JSON으로 출력하도록 재시도 1회`

#### 👩‍🏫 이해도 체크 (Checklist)
* **확인 질문**: "LLM 응답 JSON 파싱 실패 시 무한 루프 재요청 대신 '최대 1회 재시도'로 제한해야 하는 이유와 보정 프롬프트 전달 방식은 무엇일까요?"
* **자가진단 난관 지표**: JSON 파싱 에러 포착 시 재시도 횟수 상한선 없이 `while True` 무한 재요청을 돌려 API 과금 폭탄 및 프로그램 프리징을 유발함.
* **통과 기준 (이해 완료 판정)**:
  - 재시도 횟수를 측정하는 카운터 변수(`max_retries = 1`)를 둔다.
  - 1회차 실패 시 "이전 응답은 유효한 JSON이 아니었습니다. 반드시 아래 키를 포함한 완전한 JSON 형식으로 다시 출력하세요"라는 보정 문구를 주입하여 1회 재요청한다.
* **퍼실리테이터 개입 가이드**: "교육생에게 '무한 루프의 위험성을 경계하고, 외부 호출 시에는 항상 바운더리(최대 재시도 횟수)를 설정하는 안정적인 코딩 기술'을 가르친다."
* **참고 레퍼런스**: [Google Gemini API Structured Output 문서](https://ai.google.dev/gemini-api/docs/structured-output) (사전지식: 루프 및 제어 구조)

#### 🙋‍♂️ 교육생 예상 질문 & 답변 (Q&A)
* **예상 질문**: "파싱 실패 시 재요청을 보낼 때 이전 에러 메시지나 원본 응답을 프롬프트에 포함해서 전달해야 하나요?"
* **학습자 난관**: 이전 실패 맥락 없이 완전히 똑같은 프롬프트를 다시 보내 똑같은 파싱 에러 결과를 반복함.
* **기본 개념**: 
  - LLM에게 "당신이 직전에 보낸 답변 `{broken_json}`에서 `{error_msg}` 오류가 발생했습니다. Correct format spec..." 처럼 오류 원인을 피드백으로 주면 2회차에서 정상 JSON을 뱉을 확률이 극적으로 올라감.
* **퍼실리테이팅 가이드**:
  - 재요청 프롬프트 구성 시 직전 삐걱거린 응답 텍스트와 에러 내용을 덧붙이는 'Self-Correction' 피드백 패턴을 가이드한다.

### <a id="sec-13"></a>📌 [13] 데이터 연동 관점에서의 자유 텍스트 대비 JSON 구조화의 장점

#### 🙋‍♂️ 교육생 예상 질문 & 답변 (Q&A)
* **예상 질문**: "LLM이 추천 도시 이름을 '제주도', '제주 특별자치도', '제주시'처럼 제각각 내놓는데 그대로 지도 API 검색에 넣어도 되나요?"
* **학습자 난관**: AI의 유연한 출력을 그대로 외부 검색 API에 넘겼을 때 생길 수 있는 키워드 검색의 불확실성을 고민함.

  - 프롬프트 상에서 "시/군/구 단위를 우선 추천하라" 고 제약하거나, 필요시 간단한 도시명 정규화 코드를 얹어 처리함.
* **퍼실리테이팅 가이드**:
  - LLM 프롬프트에 `recommended_city` 작성 시 "예: '제주', '강릉', '속초'와 같이 검색이 쉬운 대표 도시명 1개" 로 정제하라는 예시 가이드를 추가하도록 지도한다.

### <a id="sec-16"></a>📌 [16] 장소 검색 결과 0건 시 비중단(Non-blocking) 데이터 처리
* **관련 명세**: `검색 결과가 0건이면 프로그램이 중단되지 않아야 하며, "데이터 없음" 상태로 다음 단계 진행`

#### 👩‍🏫 이해도 체크 (Checklist)
* **확인 질문**: "특정 조건에서 장소 검색 결과가 0건(빈 리스트)으로 반환되어도 예외(Exception)를 발생시키지 않고 비중단 흐름으로 처리해야 하는 이유는 무엇일까요?"
* **자가진단 난관 지표**: 검색된 장소가 없을 때 리스트의 첫 번째 원소(`places[0]`)를 참조하려다 `IndexError`가 터져 프로그램이 뻗어버리게 구현함.
* **통과 기준 (이해 완료 판정)**:
  - API 응답의 결과 리스트 길이가 0인지(`if not places:`) 체크하고, 0건이어도 빈 리스트 `[]`를 정상 반환할 수 있다.
  - 검색 실패 내역을 `errors` 목록에 사유(`type: "EMPTY_RESULT"`)로 기록하고 프로그램 실행을 계속 진행한다.
* **퍼실리테이터 개입 가이드**: "교육생에게 '맛집 정보가 없는 시골 지역이 추천되었더라도, 나머지 일정 추천 및 날씨 정보를 포함한 여행 리포트는 정상 발행되어야 한다'는 사용자 가치 관점을 심어준다."
* **참고 레퍼런스**: [Python 공식 튜토리얼 - 예외 처리](https://docs.python.org/ko/3/tutorial/errors.html#handling-exceptions) (사전지식: 파이썬 조건문 및 리스트 연산)

#### 🙋‍♂️ 교육생 예상 질문 & 답변 (Q&A)
* **예상 질문**: "맛집 검색 결과 리스트가 비어있을 때(`len(items) == 0`) `items[0]`으로 접근하다가 `IndexError`로 프로그램이 종료됩니다."
* **학습자 난관**: 배열/리스트 접근 전 범위나 원소 개수 체크(Bounds Checking)를 습관화하지 않음.
* **기본 개념**: 
  - `items[0]`과 같이 인덱서로 접근하기 전에는 반드시 `if items:` 또는 `if len(items) > 0:` 조건 검증을 통과해야 함.
* **퍼실리테이팅 가이드**:
  - 안전한 리스트 접근 구문 패턴과 0건일 때의 Early Return / Fallback 리턴 방식을 지도한다.

### <a id="sec-17"></a>📌 [17] 어댑터 패턴(Adapter Pattern)을 응용한 API 제공자 분리
* **관련 명세**: `지도/장소 API 제공자를 바꾸더라도(예: Kakao ↔ Naver) 변경 범위를 최소화`

#### 👩‍🏫 이해도 체크 (Checklist)
* **확인 질문**: "장소 검색 API 제공자를 Kakao에서 Naver로 교체할 때 메인 로직의 수정 없이 검색 인터페이스(클래스/함수)만 바꿀 수 있도록 설계하려면 어떤 구조가 필요할까요?"
* **자가진단 난관 지표**: main 코드 내부에 Kakao API 전용 요청 URL과 헤더, 파싱 로직이 하나로 거대하게 비대해져 Naver로 바꿀 때 main 함수 전체를 뒤엎어야 함.
* **통과 기준 (이해 완료 판정)**:
  - `search_places(city_name)` 공통 함수 인터페이스를 두고, 내부에서 Kakao 모듈이나 Naver 모듈을 선택적으로 호출하도록 캡슐화(Encapsulation)한다.
  - 두 제공자 모두 동일한 형식을 갖춘 딕셔너리 리스트를 반환하게 구현한다.
* **퍼실리테이터 개입 가이드**: "교육생에게 '110V 콘센트를 220V로 변환해 주는 돼지코 젠더(어댑터)처럼, 외부 API가 바뀌어도 내 메인 코드는 영향을 받지 않도록 격리하는 소프트웨어 아키텍처 패턴'을 설명한다."
* **참고 레퍼런스**: [Requests 라이브러리 공식 문서](https://requests.readthedocs.io/en/latest/) (사전지식: 함수 모듈화 및 모듈 분리)

#### 🙋‍♂️ 교육생 예상 질문 & 답변 (Q&A)
* **예상 질문**: "Kakao API와 Naver API의 검색 메서드 매개변수나 반환 형식이 달라서 코드 곳곳에 `if provider == 'kakao'` 조건을 도배하게 됩니다."
* **학습자 난관**: 구체적인 외부 구현체에 메인 비즈니스 로직이 강하게 결합(Tight Coupling)된 상태.
* **기본 개념**: 
  - `KakaoPlaceSearcher` 클래스와 `NaverPlaceSearcher` 클래스를 따로 정의하거나 각각의 전용 함수를 만들고, 이들이 반환하는 결과 데이터 규격만 표준 포맷으로 통일시킴.
  - 메인 로직에서는 `searcher.search(keyword)` 하나의 메서드만 호출하도록 단일 창구를 구성함.
* **퍼실리테이팅 가이드**:
  - 함수/클래스의 역할과 책임 분리(Single Responsibility Principle) 모범 사례 코드를 제시한다.

## 🔍 6. 에러 핸들링 & 아키텍처 모듈화 파트

### <a id="sec-18"></a>📌 [18] 단계별 에러 추적 및 errors 리스트 구조화
* **관련 명세**: `실패가 발생하면, 결과 리포트에 errors 섹션으로 요약을 남길 수 있도록 오류 목록 관리`

#### 👩‍🏫 이해도 체크 (Checklist)
* **확인 질문**: "프로그램 실행 도중 발생한 단계별 오류를 중단 없이 수집하기 위해 `errors: [{step, type, message}]` 리스트 구조로 관리하고 리포트에 포함시키는 목적은 무엇일까요?"
* **자가진단 난관 지표**: 에러가 나면 콘솔에 `print("Error")` 한 줄 치고 잊어버리거나, 발생한 오류의 맥락과 위치를 저장서류/결과 파일에 남기지 않음.
* **통과 기준 (이해 완료 판정)**:
  - 메인 프로그램 상에 `errors = []` 리스트 객체를 유지한다.
  - API 실패, JSON 파싱 재시도, 검색 결과 0건 등 비정상 상황이 발생할 때마다 `errors.append({"step": "place_search", "type": "AUTH_ERROR", "message": "HTTP 401"})` 형태 객체로 정밀 기록할 수 있다.
* **퍼실리테이터 개입 가이드**: "교육생에게 '비행기의 블랙박스 기록장치처럼, 프로그램이 완료된 후 어떤 조치나 경고가 있었는지 추적 가능하도록 진단서(errors)를 챙기는 원리'를 유도한다."
* **참고 레퍼런스**: [Python 예외 클래스 공식 문서](https://docs.python.org/ko/3/library/exceptions.html) (사전지식: 파이썬 딕셔너리 및 리스트)

#### 🙋‍♂️ 교육생 예상 질문 & 답변 (Q&A)
* **예상 질문**: "try-except 블록에서 에러를 처리했는데 에러 내용이 누락되거나 단순 문자열만 저장되어 구조적 추적이 어렵습니다."
* **학습자 난관**: `except Exception as e:` 로 잡고 단순 `str(e)` 만 적어두어 어느 단계(step)에서 무슨 오류 형태(type)가 났는지 구별이 불가능함.
* **기본 개념**: 
  - 에러 정보 객체는 규격화된 딕셔너리 구조(`step`, `type`, `message`)를 가져야 JSON 저장 및 Markdown 리포트 생성이 용이함.
* **퍼실리테이팅 가이드**:
  - helper 함수 `add_error(errors_list, step, err_type, message)`를 도입하여 예외 기록 양식을 일원화하도록 안내한다.

### <a id="sec-19"></a>📌 [19] 지도/장소 API 실패 시 맛집 섹션 데이터 없음 Fallback 처리
* **관련 명세**: `지도/장소 API 실패(네트워크/인증/쿼터 등): 맛집 섹션을 "데이터 없음" 처리하고 진행`

#### 👩‍🏫 이해도 체크 (Checklist)
* **확인 질문**: "지도 검색 API에서 401 인증 실패나 네트워크 타임아웃이 발생하더라도 전체 프로그램을 다운시키지 않고 맛집 섹션만 '데이터 없음'으로 유연하게 Fallback 처리하는 작성법은 무엇일까요?"
* **자가진단 난관 지표**: `requests.get()` 예외 발생 시 예외를 포착하지 않거나(unhandled exception), 상위로 throw시켜 전체 실행이 붕괴됨.
* **통과 기준 (이해 완료 판정)**:
  - 장소 검색 로직 전체를 `try-except requests.exceptions.RequestException:` 으로 감싼다.
  - 예외 발생 시 `errors`에 기록을 남긴 후, 맛집 데이터를 빈 리스트 `[]`로 반환하여 후속 LLM 리포트 생성 단계로 무사히 바통을 넘길 수 있다.
* **퍼실리테이터 개입 가이드**: "교육생에게 '우아한 열화(Graceful Degradation) - 일부 외부 서브시스템이 마비되어도 메인 서비스는 가능한 범위의 결과를 고객에게 선사하는 견고한 시스템 디자인'을 강조한다."

## 🐍 8. 사용된 파이썬 핵심 개념 & 함수 가이드

이 영역은 `travel_planner.py` 파일의 API 활용 국내 여행지 추천 프로그램 개발에 사용된 핵심적인 파이썬 개념과 내장 함수들을 정리한 가이드입니다.

### 1. 핵심 파이썬 개념 (Core Concepts)

#### ① 커맨드라인 인자 파싱 (`argparse.ArgumentParser`)
* **개념:** CLI(Command Line Interface) 환경에서 실행 시 인자(`-date "YYYY-MM-DD"`)를 수집하고 유효하지 않거나 누락된 옵션에 대해 도움말을 자동 생성해 주는 파이썬 표준 라이브러리입니다.
* **이유:** 단순 `sys.argv`를 사용하면 인자의 위치나 개수에 따라 `IndexError`가 쉽게 발생하지만, `argparse`를 사용하면 인자의 필수 여부(`required=True`), 도움말(`help`), 플래그 이름 지정을 안전하게 자동 처리할 수 있습니다.
* **코드 예시:**
  ```python
  import argparse

  parser = argparse.ArgumentParser(description="국내 여행 추천 CLI 프로그램")
  parser.add_argument("-date", "--date", required=True, help="여행 날짜 (YYYY-MM-DD)")
  args = parser.parse_args()

  print(f"입력된 날짜: {args.date}")
  ```

#### ② 보안 및 환경변수 관리 (`python-dotenv`, `os.environ`)
* **개념:** `.env` 텍스트 파일에 API 키를 보안 격리 저장하고, 코드 구동 시 `load_dotenv()`를 호출해 시스템 메모리의 환경변수(`os.environ`)로 읽어들이는 기법입니다.
* **비유:** 현관문 비밀번호를 집 외벽(소스 코드)에 낙서해 두지 않고, 비밀 장부(`.env`)에 적어둔 뒤 실행 시에만 열람하는 안전 관리 방식입니다.
* **코드 예시:**
  ```python
  import os
  from dotenv import load_dotenv

  load_dotenv()  # .env 파일 읽기
  api_key = os.getenv("OPENAI_API_KEY")

  if not api_key:
      print("오류: OPENAI_API_KEY가 설정되지 않았습니다.")
      exit(1)
  ```

#### ③ REST API HTTP 통신 (`requests.get`, `requests.post`)
* **개념:** 외부 웹 서버/서비스에 HTTP 요청을 보내 데이터를 주고받는 통신 메서드입니다.
* **GET vs POST:**
  - `requests.get()`: 지도/장소 검색처럼 자원을 조회할 때 URL 쿼리 파라미터(`params`)와 헤더(`headers`)를 실어 요청합니다.
  - `requests.post()`: LLM API 호출처럼 큼직한 프롬프트나 설정 옵션을 요청 본문(JSON Body, `json=...`)에 실어 생성 요청합니다.
* **코드 예시:**
  ```python
  import requests

  # Kakao 장소 검색 (GET)
  headers = {"Authorization": "KakaoAK YOUR_REST_API_KEY"}
  params = {"query": "제주 맛집"}
  response = requests.get("https://dapi.kakao.com/v2/local/search/keyword.json", headers=headers, params=params)
  data = response.json()
  ```

#### ④ JSON 구조화 데이터 파싱 및 검증 (`json.loads`, `json.dumps`)
* **개념:** LLM이 출력한 JSON 형식의 문자열 데이터를 파이썬 딕셔너리/리스트 객체로 변환(`json.loads`)하거나, 그 반대로 파이썬 객체를 JSON 텍스트로 전환(`json.dumps`)하는 작업입니다.
* **코드 예시:**
  ```python
  import json

  raw_json_str = '{"recommended_city": "제주", "weather": "온화함", "events": ["봄축제"], "reason": "봄꽃 만발"}'
  parsed_data = json.loads(raw_json_str)

  # 필수 키 4개 존재 여부 검증
  required_keys = ["recommended_city", "weather", "events", "reason"]
  if all(k in parsed_data for k in required_keys):
      print("스키마 검증 완료:", parsed_data["recommended_city"])
  ```

#### ⑤ 에러 바운더리와 Fallback 처리 (`try-except`, Graceful Degradation)
* **개념:** 지도 검색 API 호출 실패나 네트워크 오류가 발생했을 때 프로그램 전체를 다운시키지 않고, 에러를 포착하여 맛집 섹션만 "데이터 없음"으로 유연하게 대처(Fallback)하며 프로세스를 유지하는 안정화 설계 기법입니다.
* **코드 예시:**
  ```python
  places = []
  try:
      response = requests.get(search_url, headers=headers, params=params, timeout=5)
      response.raise_for_status()
      places = response.json().get('documents', [])
  except Exception as e:
      print(f"[경고] 장소 검색 API 호출 실패: {e}")
      errors.append({"step": "place_search", "type": "API_ERROR", "message": str(e)})
      places = []  # 데이터 없음 상태 유지 및 비중단 진행
  ```

#### ⑥ 객체 지향 파일 시스템 조작 (`pathlib.Path`, `os.makedirs`)
* **개념:** 결과물을 저장할 `results/` 디렉터리가 존재하는지 자동 점검하고, BOM 없는 UTF-8 인코딩으로 안전하게 원본 JSON 및 최종 마크다운 리포트를 저장하는 파이썬 I/O 방식입니다.
* **코드 예시:**
  ```python
  from pathlib import Path

  # results/ 폴더 없으면 자동 생성
  Path("results").mkdir(parents=True, exist_ok=True)

  # UTF-8 파일 쓰기
  with open("results/2026-03-15_travel_plan.md", "w", encoding="utf-8") as f:
      f.write(markdown_content)
  ```

### 2. 자주 사용되는 파이썬 내장 함수 & 메서드 (Built-in Functions)

#### ① `datetime.strptime(date_string, format)`
* **설명:** 문자열로 된 날짜 데이터가 지정한 서식(`"%Y-%m-%d"`)과 일치하는지 파싱하고 검증합니다.
* **용도:** 사용자가 입력한 날짜 문자열이 '2026-02-31'처럼 달력에 없는 날짜거나 오타일 때 `ValueError` 예외를 유발하여 잘못된 입력값을 사전 걸러냅니다.
  ```python
  from datetime import datetime

  try:
      valid_date = datetime.strptime("2026-03-15", "%Y-%m-%d")
  except ValueError:
      print("올바른 날짜 형식이 아닙니다.")
  ```

#### ② `sys.exit(code)`
* **설명:** 파이썬 인터프리터를 즉시 종료시킵니다.
* **용도:** 필수 인자(`-date`) 누락, 날짜 검증 실패, API 키 미설정 등 치명적 오류 감지 시 안내 문구를 출력한 뒤 즉시 종료(`sys.exit(1)`)합니다.

#### ③ `dict.get(key, default)`
* **설명:** 딕셔너리에서 키에 해당하는 값을 가져오며, 키가 존재하지 않을 때 `KeyError`를 내지 않고 기본값(`default`)을 반환합니다.
* **용도:** LLM 응답 JSON이나 지도 API 응답 JSON에서 특정 키가 누락되었을 때 크래시 없이 안전하게 데이터를 읽어옵니다.
  ```python
  city = parsed_data.get("recommended_city", "미정")
  ```

#### ④ `re.sub(pattern, repl, string)`
* **설명:** 정규표현식 패턴과 일치하는 문자열 부분을 지정한 텍스트로 치환합니다.
* **용도:** Naver Search API 응답 결과의 `title` 필드에 포함된 `<b>` 태그를 순수 텍스트로 정제할 때 사용합니다.
  ```python
  import re

  clean_name = re.sub(r'<[^>]+>', '', '<b>제주</b> 맛집')
  print(clean_name)  # 출력: 제주 맛집
  ```

#### ⑤ `os.path.exists(path)`
* **설명:** 지정한 파일이나 디렉터리가 실제로 시스템에 존재하는지 참(`True`)/거짓(`False`)을 판별합니다.
* **용도:** 동일 날짜로 재실행 시 기존 `results/` 폴더 내 JSON 파일 존재 여부를 확인하여 API 호출을 건너뛰는 결과 캐싱(Caching)을 구현할 때 활용합니다.
