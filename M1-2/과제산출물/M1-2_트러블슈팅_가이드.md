## 1. 이슈 1: Render 한글 Root Directory 경로 인식 불가 오류

### 🚨 발생 현상
Render Web Service 생성 시 Root Directory 항목에 `M1-2/과제산출물`을 입력하자 다음과 같은 정규식 검증 에러 발생:
```text
M1-2/과제산출물 must match re "/^[A-Za-z0-9-_./ ]*$/"
```

### 🔍 원인 분석
* Render의 대시보드 UI 및 내부 디렉토리 파서는 오직 ASCII 영문/숫자/특수기호(`A-Za-z0-9-_./ `)만을 허용하며 유니코드(한글) 경로를 거부하도록 정규식 검증이 걸려 있습니다.

### 💡 해결 방법
* **Root Directory** 입력창을 **완전히 빈칸(공백)**으로 둡니다 (GitHub 레포지토리 최상위 루트 기준 동작).
* **Build Command** 및 **Start Command**에서 따옴표를 사용하여 한글 폴더 경로를 직접 지정합니다:
  * **Build Command**: `pip install -r "M1-2/과제산출물/requirements.txt"`
  * **Start Command**: `uvicorn main:app --app-dir "M1-2/과제산출물" --host 0.0.0.0 --port $PORT`

## 2. 이슈 2: Pip 의존성 무한 역추적 및 깊이 초과 (`resolution-too-deep`)

### 🚨 발생 현상
Render 빌드 중 패키지 설치 단계에서 빌드가 중단됨:
```text
error: resolution-too-deep
× Dependency resolution exceeded maximum depth
╰─> Pip cannot resolve the current dependencies as the dependency graph is too complex for pip to solve efficiently.
hint: Try adding lower bounds to constrain your dependencies, for example: 'package>=2.0.0' instead of just 'package'.
```

### 🔍 원인 분석
* `firebase-admin`과 `google-generativeai`가 공통으로 참조하는 기반 라이브러리(`google-api-core`, `google-auth`, `protobuf` 등)의 버전 제약조건이 너무 넓게 열려 있어, 최신 `pip` 리졸버가 수백 개의 과거 배포 릴리스를 하나씩 역추적 다운로드하다가 최대 탐색 깊이를 초과함.

### 💡 해결 방법
* 하한선(Lower Bound)을 명시하거나 충돌 없는 안정 버전으로 `requirements.txt`를 명확히 고정(Pinning):
```txt
fastapi>=0.115.0
uvicorn>=0.30.0
pydantic>=2.9.2
python-dotenv>=1.0.1
firebase-admin>=6.5.0
google-generativeai>=0.8.3
openai>=1.50.0
python-multipart>=0.0.12
requests>=2.32.0
```

## 3. 이슈 3: Pydantic Rust 컴파일 에러 (`metadata-generation-failed`)

### 🚨 발생 현상
`pydantic-core` 패키지 설치 중 C/Rust 컴파일러 누락으로 빌드 실패:
```text
error: metadata-generation-failed
× Encountered error while generating package metadata.
╰─> pydantic-core
note: This is an issue with the package mentioned above, not pip.
```

### 🔍 원인 분석
* 이전 버전의 `pydantic (2.6.x)`은 최신 Python 런타임 환경에 대응하는 사전 빌드된 바이너리 휠(Pre-built Wheel)이 PyPI에 존재하지 않아 소스코드를 다운받아 로컬 Rust 컴파일을 시도했으나, 클라우드 환경에 Rust 컴파일러가 없어 실패함.

### 💡 해결 방법
* 사전 빌드된 바이너리 휠이 완벽히 제공되는 `pydantic>=2.9.2` 및 `fastapi>=0.115.0`으로 버전을 지정하여 소스 빌드 없이 0.1초 만에 바이너리로 다운로드되도록 수정.

## 4. 이슈 4: Render 미출시 Python 3.14 (`cp314`) 런타임 호환성 결함

### 🚨 발생 현상
```text
Downloading grpcio-1.81.1-cp314-cp314-manylinux2014_x86_64.manylinux_2_17_x86_64.whl.metadata
error: resolution-too-deep
```

### 🔍 원인 분석
* Render의 기본 컨테이너 이미지가 정식 릴리스되지 않은 **실험용 Python 3.14 (`cp314`)**로 실행되어, 주요 AI 패키지(`grpcio`, `firebase-admin`)의 공식 빌드 휠이 없어 무한 탐색 오류 유발.

### 💡 해결 방법
1. 프로젝트 루트 및 산출물 폴더에 **[`.python-version`](file:///c:/Users/pnlkc/AIProject/Codyssey/M1-2/%EA%B3%BC%EC%A0%9C%EC%82%B0%EC%B6%9C%EB%AC%BC/.python-version)** 파일 생성:
   ```text
   3.11
   ```
2. Render 대시보드 `Environment` 탭에 환경변수 추가:
   * **Key**: `PYTHON_VERSION`
   * **Value**: `3.11.9`
3. 표준 안정 런타임인 Python 3.11 환경으로 전환되어 모든 패키지 단번에 정상 설치 완료.

## 5. 이슈 5: Render 헬스체크 프로브 거부 (`405 Method Not Allowed - HEAD /`)

### 🚨 발생 현상
서버 구동 직후 Render의 내부 로드밸런서 로그에 405 에러 기록:
```text
INFO: Uvicorn running on http://0.0.0.0:10000
INFO: 127.0.0.1:55080 - "HEAD / HTTP/1.1" 405 Method Not Allowed
```

### 🔍 원인 분석
* FastAPI의 `@app.get("/")` 데코레이터는 기본적으로 `GET` 메서드만 수신합니다. Render 클라우드의 가동 상태 감시 봇(Healthcheck Probe)은 트래픽을 아끼기 위해 본문 없는 `HEAD /` 요청을 전송하므로 405 Method Not Allowed가 발생함.

### 💡 해결 방법
* `main.py`의 메인 라우트 및 헬스체크 라우트에 `HEAD` 메서드를 명시적으로 허용:
```python
# main.py
@app.api_route("/api/health", methods=["GET", "HEAD"], tags=["System"])
async def health_check():
    ...

@app.api_route("/", methods=["GET", "HEAD"], include_in_schema=False)
async def serve_index():
    ...
```

## 6. 이슈 6: Firestore 정렬 쿼리 시 모듈 누락 (`NameError: name 'firestore' is not defined`)

### 🚨 발생 현상
대화 목록 조회 API(`GET /api/conversations`) 호출 시 500 에러 발생:
```text
[ERROR] Firestore get_all_conversations 에러: name 'firestore' is not defined
```

### 🔍 원인 분석
* `services/firestore_service.py`에서 Firestore 정렬 방향 상수인 `direction=firestore.Query.DESCENDING`을 호출했으나, 파일 상단에 `firestore` 모듈 임포트가 누락되어 발생한 NameError.

### 💡 해결 방법
* `firestore_service.py` 상단에 안전 임포트 구문 추가 및 동적 방어 코드 적용:
```python
# services/firestore_service.py
try:
    from firebase_admin import firestore
except ImportError:
    firestore = None

# 쿼리 시 안전 참조
direction = firestore.Query.DESCENDING if (firestore and hasattr(firestore, "Query")) else "DESCENDING"
docs = db.collection("conversations").order_by("updated_at", direction=direction).stream()
```

## 7. 이슈 7: Vercel 정적 배포 시 Python uv 런타임 충돌

### 🚨 발생 현상
Vercel에 배포 푸시 시 빌드 실패:
```text
Using uv 0.10.11
Creating virtual environment at "/vercel/path0/M1-2/과제산출물/.vercel/python/.venv"...
error: No interpreter found for Python 3.11 in managed installations
```

### 🔍 원인 분석
* Vercel은 **정적 프론트엔드(HTML/CSS/JS)** 호스팅용인데, 같은 레포지토리에 `requirements.txt`가 존재하자 Vercel이 이를 Python Serverless 프로젝트로 오인하고 파이썬 빌드를 시도하다 에러가 발생함.

### 💡 해결 방법
1. **[vercel.json](file:///c:/Users/pnlkc/AIProject/Codyssey/M1-2/%EA%B3%BC%EC%A0%9C%EC%82%B0%EC%B6%9C%EB%AC%BC/vercel.json)**에 순수 정적 웹(`@vercel/static`) 빌더를 명시:
   ```json
   {
     "version": 2,
     "name": "ai-assistant-dashboard",
     "builds": [
       { "src": "index.html", "use": "@vercel/static" },
       { "src": "css/**", "use": "@vercel/static" },
       { "src": "js/**", "use": "@vercel/static" }
     ],
     "routes": [{ "src": "/(.*)", "dest": "/$1" }]
   }
   ```
2. **[`.vercelignore`](file:///c:/Users/pnlkc/AIProject/Codyssey/M1-2/%EA%B3%BC%EC%A0%9C%EC%82%B0%EC%B6%9C%EB%AC%BC/.vercelignore)** 파일로 백엔드 파이썬 파일 빌드 시도를 완전히 제외시켜 Vercel 빌드 속도를 3초로 단축.

## 8. 이슈 8: 멀티 도메인 환경에서의 Swagger 404 및 초기 DB 비어있음 현상

### 🚨 발생 현상
1. Vercel 화면에서 `📑 Swagger API` 버튼 클릭 시 404 에러 발생.
2. Vercel 접속 시 상단 뱃지가 `Local Mock Engine`으로 뜨거나 통계 데이터가 `0개`로 조회됨.

### 🔍 원인 분석
* **Swagger 404**: Vercel을 정적 사이트로 분리하면서 `/docs`는 FastAPI가 동작하는 Render(`https://codyssey-m1-2.onrender.com/docs`)에만 존재하는데, 프론트엔드가 상대경로 `/docs`로 이동하려 함.
* **Mock Engine 및 데이터 0개**: 
  - 프론트엔드 `js/api.js`의 기본 API 엔드포인트가 Render 주소로 바인딩되지 않았음.
  - 새로 생성된 클라우드 Firestore의 `data` 컬렉션이 비어있는 상태였음.

### 💡 해결 방법
1. **프론트엔드 API 엔드포인트 바인딩 ([js/api.js](file:///c:/Users/pnlkc/AIProject/Codyssey/M1-2/%EA%B3%BC%EC%A0%9C%EC%82%B0%EC%B6%9C%EB%AC%BC/js/api.js) & [index.html](file:///c:/Users/pnlkc/AIProject/Codyssey/M1-2/%EA%B3%BC%EC%A0%9C%EC%82%B0%EC%B6%9C%EB%AC%BC/index.html))**:
   * 로컬(`localhost`)이 아닌 배포 환경일 때 `API_BASE`를 `https://codyssey-m1-2.onrender.com`으로 자동 라우팅.
   * Swagger 버튼 클릭 시 Render 백엔드의 `/docs`로 바로 열리도록 설정.
2. **Firestore 데이터 자동 시딩 (Auto-Seeding 탑재)**:
   * [services/firestore_service.py](file:///c:/Users/pnlkc/AIProject/Codyssey/M1-2/%EA%B3%BC%EC%A0%9C%EC%82%B0%EC%B6%9C%EB%AC%BC/services/firestore_service.py)에서 Firestore 컬렉션이 비어있으면 `sample_timeseries.json`의 **120개 초기 데이터를 1회 배치로 자동 등록**하도록 구현.
